开发一个离线身份裁定服务，供园区根据人事部门签发的合成证明判断指定人员在某日能否使用某区域。使用 Windows 原生 Python 3.12 和标准库，可用 SQLite。所有部门、身份、日期和凭证由本地夹具生成，无外部系统或真实个人数据。需要实现 ingest、decide、history 和 verify 命令。

证明有人员、来源部门、有效区间 [from,to)、不可变事件 ID、该来源的序号和授权或撤销结论。一个证明的业务生效日和本系统知悉它的事务序号是两条时间轴。更正须引用该来源中已有事件，说明要替换的一段有效区间及新结论；区间外保留原结论，连续更正必须指向该段当前版本。每批按来源和序号验证；同一 ID 同内容只记一次，内容冲突、来源冒用、序号缺口、悬空引用、并行改写同一段均拒绝整个批次。来源序号可以跨批次，系统事务序号只在成功提交时增长。批内更正可指向较早序号的同批事件。

decide 传入人员、区域、业务日 D 和知悉序号 K。对指定区域先按随输入提供且可版本化的来源清单筛出主管部门。只用在 D 有效且截至 K 可见的事实：任一主管部门撤销即拒绝，否则至少两个不同主管部门授权才通过。输出唯一稳定的解释：有撤销则取按部门 ID 排序的首个撤销；通过则取排序最前的两个授权；证据不足按部门列出缺席或无有效结论。history 输出两轴变化的最少合并区间，并能用证据 ID 解释任何分界。主管清单变动也须遵守 D、K 双轴，批中证明与清单一起发布。

交付可执行代码、README、可重建输入和测试。必测 D 恰在端点、迟到撤销使相同 D 在不同 K 得到相反裁定、更正只改变中间区间、同一来源多份证明不充当双签、批次后半错误导致证明及主管清单同时回滚，以及故障后旧 K 的答复字节一致。用独立的小数据逐日逐事务参考实现对比 history。
